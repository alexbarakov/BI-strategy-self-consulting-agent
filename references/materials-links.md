# Links: what to publish and what to leave as a placeholder

The rule is simple. **Public material is linked directly. Anything internal to a company is a placeholder the participant fills in themselves.**

## Public — link freely

- `strategy-template.md` — the analysis frame of 7 blocks + block → materials mapping
- `BI Project Health Check.xlsx`, `D&A Strategy & Tactics Planner [ENG].xlsx` — the working templates; copy them into `<Company>/templates/` and link by relative path so they become downloadable on a built site
- Primary sources cited in `evidence-2026.md` and `kb/51-numbers.md` — always inline, next to the figure, not only in a "materials" block at the end
- The companion repository [DG Board KB](https://github.com/alexbarakov/DG-strategy-self-consulting-agent)

## Placeholders — the participant fills these in

Internal wiki pages, dashboards, ticket queues, chat channels, metric registries and catalogs. Write them as an explicit placeholder rather than inventing a plausible URL:

```
- Internal: <link to your data catalog>
- Internal: <BI usage dashboard, 90 days>
```

A reference wiki in the current format is a **format sample, not a data source**. Numbers, targets and names from any reference strategy are never carried into a deliverable.

## Why this matters

An invented internal link is worse than an absent one: it looks authoritative, and the first person who clicks it loses trust in everything else on the page.
