The canonical spine of the method. The guide is a 22-sheet workbook in 5 sections. **The order of the sheets is the order of the work**: fill them in left to right, each one resting on the previous.

The author defines a BI strategy as **a repeatable exercise made of four activities**: a deep analysis of needs and of the D&A landscape -> reassembling the high-level vision and goals -> working out concrete solutions and practices -> planning the team's work for the next six months.

## Sections and sheets

| # | Section | Sheets |
|---|---|---|
| **1** | **AS-IS analysis** - needs, landscape, constraints | 1.1 D&A PainPoints · 1.2 Data Domains Classification · 1.3 User Classification and BI Models · 1.4 Info supply-demand matrix · 1.5 Outside BI · 1.5 Inside BI |
| **2** | **TO-BE design** - target roles, processes, tools | 2.1 Data Mgmt processes + questionnaire + Critical data · 2.2 Content Mgmt Processes + questionnaire · 2.3 SelfServ D&A Practices · 2.4 Centralized D&A Practices + Analytical Workplaces · 2.5 BI & Around BI Tools |
| **3** | **Operating model and efficiency** | 3.1 Access Matrix · Regular Meetings · Rules and Standards · 3.2 Newcomer onboarding plan · 3.3 BI Project Metrics |
| **4** | **Transformation plan** | 4. Action plan |
| **5** | **New D&A vision** | 5. BI Vision |

## How this maps onto the skill's seven blocks

The guide is the source; `strategy-template.md` is the output.

- section 1 -> blocks 1-2 (AS-IS)
- section 2 -> blocks 3, 4.1, 4.2, 4.3, 5 (TO-BE)
- section 3 -> block 6 (the operating foundation)
- sections 4-5 -> block 7 (transformation) and the vision

## The rule of application

Every sheet is **an exercise with worked examples**, not theory. What must survive into the participant's artifact is a filled-in table, not a retelling of the frame. If a sheet cannot be filled in because the data does not exist, that is a finding for block 2, not grounds for skipping the sheet.
