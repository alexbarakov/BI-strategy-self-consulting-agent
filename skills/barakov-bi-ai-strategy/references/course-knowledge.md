# Библиотека концептов курса (грунт для рекомендаций)

Генеричная выжимка фреймворков курса «Разработка BI+AI стратегии» — чтобы рекомендации в блоках были грамотными при запуске у любого участника, без опоры на данные конкретной компании. **Цифры здесь — общеотраслевые/учебные ориентиры, а не таргеты компании**; таргеты участник ставит сам (в дорожной карте — заглушки `<•>`).

## Сквозная рамка
- **«AI генерирует черновик — человек проверяет».** Детерминированного ответа в аналитике нет автоматической верификации, поэтому нужен human-gate.
- **Двойственная стратегия:** «старый BI» (понятные практики: core, сертификация, health-score) + «новый BI» (эксперименты: semantic-first, агенты) под kill-gates. Ответ на AI-FOMO.
- **Стратегия = цепочка зависимостей, а не список фич.** AI-фичу нельзя ставить раньше её звена.

## Занятие 1 — тренды и трезвость
- **Traditional → Agentic BI:** conversational AI как главный интерфейс ad-hoc/self-service; дашборды → нишевый мониторинг. **Headless BI** = 3 слоя (Data products + Semantic layer + AI interface).
- **AI-пузырь:** ~95% пилотов не масштабируются; GenAI — seniority-biased change (падает найм джунов). Карго-культ vs реальные «летающие самолёты».
- **Компромиссный сценарий (рамка):** эффекта пока мало; растут core/semantic/governance/агенты; синьоры вайбкодят лучше; эффект в новых задачах (100% вместо выборки); главные «стены» — review-bottleneck и недобор контекста.

## Занятие 2 — спрос и потребители
- **Агент — новый класс потребителя**; ему нужна машиночитаемая семантика (ключи, valid ranges, свежесть, owner), а не «спроси у Маши».
- **4 типа неопределённости ad-hoc:** формулировка / поиск объекта / доверие / интерпретация — разная автоматизируемость.
- **Данные против хайпа:** пользователи чаще просят чинить поиск и доверие, чем добавлять разговорный AI.

## Занятие 3 — ассессмент + AI-readiness
- **Две оси зрелости:** классическая BI-maturity × AI-readiness.
- **AI Ready Domain Score** (генерично): роли + здоровье метрик/витрин/дешей + полнота доменной базы знаний (ДБЗ) + готовность процессов к «AI генерирует—человек проверяет»; зоны Green/Yellow/Red/Critical.
- **Зрелость по размеру компании:** небольшим/не-техам — не строить свою GenAI-инфру, качать Core BI + 1 пилот; лидерам — делить ресурс DG/R&D/инфра.

## Занятие 4 — каналы BI
- **Треугольник Centralized — Self-Service — Agentic.** AI каннибализирует ручные ад-хоки и разовые дэши, не сертифицированный репортинг.
- **4 стадии agentic:** Interoperability → Composability → Managed Autonomy → Multi-Agent. Анти-паттерн «агент = чат-бот без инструментов».
- **Парадокс Жевонса:** дешевле контент → больше хаоса. Защита: reuse by default, AI-объект = временный черновик с автоархивацией.

## Занятие 5 — data management
- **Core-слой = «здоровое питание» AI:** сертифицированные витрины (ownership, SLA, DQ, мета), reuse вместо «ещё одна витрина».
- **Цепочка зависимостей:** core → сертификация метрик (semantic) → доменный контекст → точность AI → self-service.
- **AI в DM уже сейчас:** генерация DQ-проверок и описаний; считать 100%, а не выборку; новый bottleneck — поток инцидентов (нужен incident/eval-агент).

## Занятие 6 — content management
- **AI slop:** контент множится быстрее разбора; сертификация и архивация → защитная инфраструктура.
- **Health Score:** штрафы (нет владельца, неиспользуемость, заброшенность, дубли) × мультипликаторы (высокий WAU, использование руководством); это trust-сигнал и для агента.
- **Прожарка ботом, фидбек-бот, датавиз-оговорка** (упарываться только если операционный деш И живёт долго; 95% — BANs/бары/таблицы), target audience как поле контента.

## Занятие 7 (AI-фундамент) — semantic, core, контекст
- **Триада пререквизитов:** semantic layer + trusted core + ДБЗ (фьюшоты). Без неё text-to-SQL угадывает.
- **Цифры-ориентиры:** enterprise text-to-SQL ~40%; сложные бенчмарки ~6% против ~86% академических; semantic layer поднимает до 85–95% и «честно падает».
- **Таксономия отказов text-to-SQL:** entity resolution («какие именно»); джойны/фан-аут; пропущенные фильтры; гранулярность времени/таймзоны; оконная логика/мёртвый код. Лечится семантикой, known joins, few-shots, judge-gate.
- **Контекст как слой:** «MCP — водопровод, а не смысл». Не работает: каталоги-полки, онтологии (SME-bottleneck), авто-докуметация ~75% (отравляет). Работает: майнинг истории запросов + узкий human-gate + проверенные пары «вопрос→SQL».
- **Context Management System:** Context Unit (inferred→candidate→verified→deprecated, provenance, freshness TTL, ссылка на SSOT); trust-плоскость SERVE_AS_FACT / WITH_CAVEAT / WITHHOLD; PreToolUse-хук — агент не пишет SQL без контекста.

## Занятие 8 — агентная архитектура
- **Слои:** MCP-серверы → оркестратор + атомарные скиллы → judge-gate/guardrails (RELATIVE-ONLY: направление, не абсолюты) → eval-инфра (golden set, judge runner).
- **Математика точности:** 7 шагов по 90% → <50% на выходе. Меньше шагов, больше детерминизма, judge на выходе.
- **Legacy BI:** AI-стратегия старого инструмента начинается с архитектуры (распил монолита), а не с чат-бокса. Build vs buy: тонкий свой слой поверх коммодити.

## Занятие 9 — команда и профессия
- **Сдвиг работы BI dev:** падают дашборды/DWH/adhoc, растут core/semantic/ДБЗ/агентская разработка. Команды-фабрики сжимаются, вымывается джун-мидл; нужен «кожаный посредник».
- **BDE / Analytics Engineer** — роль на бизнес-юнит (метадата, качество, core). **Вайбкодинг** — обязательный тулинг (оптимум ~30–50% AI-кода; синьоры лучше; review — bottleneck).
- **Playbook setup → evaluate:** H1 окружение всем без квот → H2 адопшен в ревью/грейды. AI-акселератор — разгон снизу.

## Занятие 10 — метрики и kill-gates
- **Метрики AI-стримов:** auto-response rate, точность на golden set, hallucination rate, extra FTE capacity, cost per successful task.
- **Честный eval:** «метрика хороша настолько, насколько строг её судья»; наполнение ≠ доверие ≠ эффект (coverage и false-accept читать вместе).
- **Kill-gate:** метрика/порог/СТОП у каждой инициативы. **Экономика:** net = saved hours × rate − (токены + подписки + люди); без вычета знаменателя окупается всё.

## Занятие 11 — action plan и Vision
- **Stack-rank:** Governance → Trusted Data → AI-готовность → BI Content → Self-service (режем справа налево).
- **Реестр рисков:** хрупкая цепочка AI→SL→core→каталог; агенты умножают хаос; governance без ресурса.
- **Финальный тезис:** смысл — в настоящем; строить AI-ready архитектуру и следить.

## Экспертные усиления (для рекомендаций)
- **Обратимость ставок:** обратимые — делать смело; необратимые (хедкаунт, отказ от core, публичные AI-ответы) — через kill-gate.
- **Provenance footer:** источник + свежесть + владелец в каждом ответе — дешёвая защита от silent failures.
- **Observability как P0:** без трейсинга и разметки success нельзя доказать эффект и гейтить eval.
- **«Готов по баллу ≠ отвечает верно»:** AI Ready Score меряет полноту, не прод-точность → eval-gate до анонса домена.
- **ADKAR для AI:** типичный провал — сделать Knowledge+Ability, пропустив Awareness+Desire.
